# 課序 1.9.0：把 115-MI 新功能併回共用主程式，讓 115-1-AP2 也能用（Claude 撰寫規格，2026-10-13）

## 0. 背景與原則

115-MI 和 115-1-AP2 **共用同一套課序主程式**，但課程內容、題庫、資料、部署各自獨立。

這幾天的新功能都是在 115-MI 分支開發的（`codex/115-mi-assessments`，`a593796..70354e0`），而且把課程代碼 `115-1-MI-國考精準對焦` 寫死在程式裡。
本次要把這些功能**通用化**後併回主程式：AP2 可以用，115-MI 照常運作，兩邊的程式碼回到同一份。

**不能動的東西**：
- 兩邊既有的資料，包括正式前後測紀錄、互動紀錄、成績、名冊、題庫。
- 兩個 Firebase 專案（`ap2-7ed91`、`mi-bd885`）都**只能在教師授權後部署**，而且每條指令都要明確帶 `--project`。

## 1. 要併入的功能

| 功能 | 115-MI 來源 commit | 通用化方式 |
|---|---|---|
| 正式前後測（私有答案、手動開放／結束／公布、補考理由、配對 CSV） | fe814dd、c33dbe7、d48aac8（種類切換修正） | 每門課自己設定前後測題目來源（`assessmentSources`）。`MI_EXAM_IDS` 改成課程設定。CSV 檔名改為 `<課程代碼>_前後測配對.csv`。 |
| 授課控制台（單螢幕簡報、黑屏、備註、進度與測驗控制） | 1b3b4fe | 簡報存在各課程自己的 `teacherAssets/presentation`。沒有匯入簡報的課程，控制台只顯示進度與測驗分頁。 |
| 課堂互動（全選項版、狀態列、綁定投影片、倒數與加時） | c2c1b1e、70354e0 | 互動題目從程式常數改成課程資料，存在 `courses/{id}/classroomConfig/interactions`。115-MI 的 12 題寫成 migration 匯入。 |
| 影片續播等待進度修正 | d48aac8 | 本來就是通用修正，直接併入。 |
| 1.8.0 開放式反思活動 | reflection-activity 分支 ec8947f | 一起併入；Claude 會在本次驗收時一併審查。 |

**不要併入**（這些只屬於 115-MI 網站）：
- 115-MI 網站內容：只保留微免教材、移除 AP2 教材、catalog 只留兩筆、`MATERIALS_BASE_URL` 指向 MI、刪除 AP2 教材快照測試、三份 CHP 舊教材。
- 這些差異改成「每個網站一份建置設定」處理，見第 3 節。

## 2. 功能開關：每門課自己決定

- 在課程設定加 `features: { assessments, teachingConsole, classroomInteraction }`，預設全部關閉。
- 教師在後台「課程設定」勾選要開哪些功能。
- 所有寫死 `115-1-MI-國考精準對焦` 的地方（`shared/classroom.ts`、`functions/src/classroom.ts`、`functions/src/teaching.ts`、`src/App.tsx`、`src/ClassroomInteraction.tsx`）都改成：讀取課程的 `features`，再搭配既有的 `access()` 驗證。
- **後端以課程設定為準**：功能沒開的課程，對應的 API 一律拒絕。
- 課堂互動的路徑改成用 `courses/{courseId}/classroomState`、`classroomRounds`，不再寫死課程代碼。
  - 115-MI 現有資料原本就放在這個路徑之下，**不需要搬資料**；部署前要確認這一點。

## 3. 兩個網站各自的建置設定

- 新增建置變數 `VITE_SITE_ID`（`ap2` 或 `mi`），或一份 `site.config.json`，用來決定：
  - 教材目錄要包含哪些教材；
  - `MATERIALS_BASE_URL`；
  - 要不要發布 CHP 舊教材。
- 測試要依網站分開跑，**兩種設定都必須全過**。
- 目標：兩個 repo 用**同一份程式碼**，只有建置設定和 GitHub variables 不同。

## 4. 115-MI 的遷移（部署前準備好，教師授權後才執行）

- 寫一支 migration 腳本，只寫入 `mi-bd885`：
  - 把 115-MI 課程的 `features` 三項都設為開啟；
  - 把 12 題互動定義寫入 `classroomConfig/interactions`，內容和目前程式常數逐字相同。
- 腳本要支援 dry-run，先輸出預計寫入的內容，給 Claude 比對。
- 部署順序：先跑 migration，再部署 MI 的 Functions 與前端。
  - 部署後要確認：115-MI 舊的互動輪次、前後測紀錄、簡報都能正常讀取。

## 5. AP2

- 合併後，AP2 的課程預設**所有新功能都是關閉的**，學生和教師看到的畫面與現在完全相同。
- 部署要等 Claude 驗收、教師授權，並用 AP2 既有的 `scripts/deploy.sh`。
- 教師想在 AP2 某門課使用時，到後台勾選功能即可。
- AP2 的互動題目、簡報、前後測題目之後另外製作，不在本次範圍。

## 7. 測試（不得略過、不得刪除既有測試）

- **AP2 設定**：既有 AP2 教材快照等測試全部保留並通過。
- **MI 設定**：MI 的教材與 catalog 測試通過。
- **功能開關**：
  - 功能關閉時，每個新 API 都要拒絕；
  - 開關只影響該課程，不影響其他課程。
- **相容性**：
  - 115-MI 舊資料：沒有 `deadlineAt` 的舊輪、舊的 `latestRoundId` 都要能讀；
  - migration 用 dry-run 比對，12 題內容與程式常數完全一致。
- 原有的課堂互動、前後測、授課控制台、反思測試全部保留。
- `npm run check` 要用 AP2 與 MI 兩種設定**各跑一次**，都要全過。

## 8. 學生端使用說明（教師 10/13 追加，本次一併完成）

依 `docs/STUDENT_GUIDE_PLAN.md`（第一～六節＋文末「教師決定」）實作，重點：

- **形式**：靜態頁 `public/guide/index.html`，不需登入、不經 Firebase、無外部相依，手機單欄、可列印；沿用站內色系與字級變數。
- **入口**：登入頁按鈕下方「第一次使用？看使用說明」；學生首頁 `prefs-bar`「？使用說明」。
- **首次提示卡**：`Student.tsx` 一次性 3 張（待辦在哪、單元頁分頁、完成度怎麼算），可略過；以 courseId＋uid 記在 localStorage（try/catch），不寫雲端、不影響進度。
- **內容**：計畫第三節 1–10，加上 1.7.x 與 1.9.0 新功能段落（每段標「老師有開放時才會看到」）：
  - 正式前後測：老師開放才出現；限時、只有一次；交卷後不顯示答案，老師公布後才看得到成績；斷線或沒交到要找老師，不要重新登入別的帳號。
  - 課堂互動：老師在投影片開放時手機會出現題目；看倒數；送出後不能改；時間到就停止收件，等老師公布結果。
  - 開放式反思：在課序單元內作答，送出前可修改的規則依 1.8.0 實作寫。
  - 影片會記住播放位置。
- **兩站共用**：同一份頁面；課程名稱、網站網址從網站建置設定（第 3 節）帶入。AP2、MI 各自 build 出來的說明頁都要檢查。

- **測試**：未登入可開啟；兩種網站設定都要有入口連結；390 寬無水平溢位、字 ≥12px；色系與字級切換有效；提示卡可略過且不再出現。
