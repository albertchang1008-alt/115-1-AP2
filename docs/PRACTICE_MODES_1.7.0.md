版本：1.7.0（`npm run version:sync`）
本檔即為 Claude 專案文件 `claude/1.7.0-練習模式與綜合練習規格.md` 第三版的 repo 副本，以本檔為準。
第三版變更：新增第 3.6 節「錯題跨版本延續」與第 4 個 commit。
第二版變更：錯題移除改為「標記已移除、保留次數」；錯題分「今天剛錯／待複習」兩群；拿掉錯題時間範圍；錯題複習可選題數。

## 0. 教師的決定（2026-10-06）

1. **名稱與行為一致**：「閃卡」＝翻卡；「錯題複習」＝只出錯題、逐題重做。
2. **閃卡正面要給選項**（題幹＋選項），翻面看正解與解析。
3. **錯題移除條件**：答錯之後的**另一天**答對才移除；同一天答對只標「今天已答對」。
4. **新的翻卡閃卡取代現在的作答型「完整閃卡」**。
5. 綜合練習加入範圍選擇：**依單元分組勾選，可展開到次單元，預設全選**；提供閃卡、抽題、錯題複習三種練習。
6. 只有完整測驗計分（1.6.0 決定不變）。
7. **移除時保留答錯次數**，只標記「已移除」；之後又答錯，接著累加。
8. **拿掉錯題時間範圍選單**（推翻 1.3.0），改用第 3.3 節的兩群分法。
9. **錯題複習可選題數 10／20／30／50**。
10. **題庫同步新版本時，錯題不再整個清空**：題目還在且正解沒變的，錯題紀錄帶到新版本；正解改變或被刪除的題目才重置（第 3.6 節）。

學習面的理由（寫進 handoff）：重做錯題是提取練習，比看答案有效；同一天看完解析立刻答對多半靠短期記憶，隔天再答對才算學會。因此**今天剛錯的題目交給閃卡看解析，隔天以後交給錯題複習重做**。保留答錯次數並跨版本延續，讓「老是錯的題目」不會因為教師修一個錯字就消失。

## 1. 先盤點（動工前回報，結果寫進 handoff）

1. **錯題資料結構**：`progress.units[unitId].wrong` 現在是 `Record<version, string[]>`，還是 1.3.0 第六版的「次數 `n`＋最後答錯時間 `at`」？錯題時間範圍選單是否已實作、出現在哪些畫面？
2. **各模式現況**：完整閃卡、抽題、錯題（按鈕叫「錯題複習」）實際是翻卡還是作答？各自寫入哪些欄位？`submitAttempt` 的 `mode` 有哪些值？
3. **答對時錯題如何更新**：答對即移除、整份覆蓋，還是不更新？
4. **綜合練習**：`MixedPractice` 的候選分類篩選條件（是否只含「目前學習」、是否含已考完單元、選看單元、`isReviewUnit` 排除）；題庫何時載入；補題規則；`submitMixedAttempts` 支援哪些模式、錯題與 `attempted` 是否寫回各分類。
5. 複習考的「錯題」按鈕現在是翻卡還是作答；複習考是否有自己的題庫版本與錯題紀錄。
6. 所有讀取「錯題數」的地方（首頁、單元列、教師端學生進度、匯出），列出清單，改結構後都要改成只算有效錯題。
7. **跨版本延續的前提（第 3.6 節，第 4 個 commit 用）**：
   - **題目 ID 是否跨版本固定**（同一題在新版本是否沿用同一個 ID；`attempted` 跨版本累計是否就是依賴這點）。
   - 同步新版本的流程在哪個函式、步驟順序為何；**同步當下能否同時取得舊版與新版的正解**（伺服器專用答案表是否在覆寫前可讀）。
   - 首頁已讀取的分類（Unit）資料裡，能否放一個小欄位而不增加讀取。
   - 任一前提不成立：**第 1 至 3 個 commit 照常完成，第 4 個 commit 不做**，在 handoff 說明原因與替代方案。

盤點與本規格衝突時先回報再改；不明確的地方以本規格為準。

## 2. 四種模式（單元與綜合練習共用）

| 模式 | 形式 | 回饋時機 | 計分 | 寫入 |
|---|---|---|---|---|
| 完整測驗 | 該分類全部題目作答 | 交卷後 | **是** | `best`、`passedAt`、`fullAttempts`、錯題、`attempted` |
| 閃卡 | 翻卡（題幹＋選項 → 翻面看答案） | 翻面即看 | 否 | **不寫入任何資料** |
| 抽題練習 | 逐題作答 | 每題立即 | 否 | 錯題、`attempted` |
| 錯題複習 | 只出「待複習」錯題，逐題重做 | 每題立即 | 否 | 錯題（依第 3.2 節）；不寫 `attempted` |

逐題立即回饋沿用既有抽題流程：選擇 →「送出答案」→ 顯示對錯與解析、鎖定選項 →「下一題」／「查看結果」。

## 3. 錯題資料與規則

### 3.1 結構
```ts
// progress.units[unitId].wrong[version][questionId]
interface WrongEntry {
  n: number;    // 累計答錯次數（移除後保留）
  at: number;   // 最後答錯時間（伺服器毫秒）
  ok?: number;  // 「今天已答對」的時間；只在與 at 同一天答對時寫入
  rm?: number;  // 已移除的時間；有此欄位＝不在錯題表中
}
```
- **有效錯題**＝沒有 `rm` 的項目。畫面上所有「錯題數」、錯題表、排序、綜合練習的錯題合計，一律只算有效錯題。
- 舊資料相容：`string[]` 讀取時視為 `{ n: 1, at: 0 }`；已是 1.3.0 結構則只新增 `ok`、`rm`。下次寫入時轉成新結構，不做批次遷移。
- 依題庫版本分開儲存；換版本時依第 3.6 節延續。
- **所有讀取錯題的地方都必須經過同一個純函式**（例如 `effectiveWrong(unitProgress, unitMeta, currentVersion)`，前後端共用），不得各自直接讀 `wrong[version]`。

### 3.2 更新規則
適用：完整測驗、抽題、錯題複習、綜合練習的抽題與錯題複習。**閃卡不適用。**

- **答錯**：
  - 沒有紀錄 → 新增 `{ n: 1, at }`。
  - 有紀錄（不論是否已移除）→ `n + 1`、`at = 交卷時間`、刪除 `ok` 與 `rm`（已移除者回到錯題表，次數接著累加）。
- **答對**（只處理有效錯題；已移除或沒有紀錄的不變）：
  - 交卷時間的日期**晚於** `at` 的日期 → 寫入 `rm = 交卷時間`、刪除 `ok`。
  - 同一天 → 寫入 `ok = 交卷時間`，仍是有效錯題。
- 日期以 **Asia/Taipei 日曆日**判定，伺服器以固定 UTC+8 計算。
- `at: 0`（舊資料）視為很早以前答錯，答對即標記移除。
- 全部在伺服器重批後計算，前端送來的對錯一律不採信（既有原則）。
- 寫入前若目前版本尚無錯題資料，先依第 3.6 節把延續的紀錄**實體化**到 `wrong[目前版本]`，再套用本節規則。

### 3.3 兩群分法（取代時間範圍）
有效錯題依 `at` 的日期分成：
- **今天剛錯**：`at` 的日期＝今天（含今天又答對、有 `ok` 的）。
- **待複習**：`at` 的日期早於今天。

| | 今天剛錯 | 待複習 |
|---|---|---|
| 閃卡 | 排最前面 | 排在今天剛錯之後 |
| 錯題複習 | 不出 | **只出這群** |
| 抽題與綜合練習的「錯題優先」 | 不算錯題群，歸「其他」 | 優先出 |

- **移除錯題時間範圍選單**：若已實作，在首頁錯題卡、單元頁、成績摘要頁等所有出現處移除選單與路由參數（`range=`）；舊網址帶 `range` 時忽略。
- 「今天」以使用者打開畫面時的 Asia/Taipei 日期判定；重新進入畫面時更新即可。

### 3.4 顯示
- 單元頁按鈕：「錯題複習（18 題）」，數字＝待複習題數；若有今天剛錯的題目，下方小字「另有 5 題今天剛錯，明天起可重做」。
- 待複習 0 題、但有今天剛錯：按鈕仍可點，顯示「這 5 題今天剛錯，先用閃卡看解析，明天再來重做」＋「用閃卡看解析」按鈕。
- 有效錯題 0 題：按鈕維持 1.6.0 樣式（虛線淡字、可點、顯示「目前沒有錯題」）。
- 錯題複習開始前說明一行：「答錯後隔天以上再答對，才會從錯題移除。」
- 錯題複習結果頁：「已移除 a 題・仍答錯 b 題」。抽題、完整測驗、綜合練習的結果頁若有錯題答對，另顯示「移除錯題 a 題・今天已答對 c 題（明天以後再答對就會移除）」。
- 其他「錯題 k」顯示（分類列、首頁、教師端）＝有效錯題總數（兩群合計）。

### 3.5 錯題複習的出題
- 範圍：待複習的錯題。
- 題數按鈕 **10／20／30／50**：超過待複習題數的檔位停用；待複習題數不等於任一檔位且 ≤ 50 時，另加「全部 X 題」。例：37 題 → 10、20、30 可按，50 停用，加「全部 37 題」。超過 50 題時只有四個檔位。
- 排序：答錯次數 `n` 多的在前；次數相同時，`at` 較早的在前；取前 N 題後**再洗牌出題**。
- 手機 `練習 ▾` 選單：「錯題複習」展開為 10／20／30／50／全部 X 題，規則同上。

### 3.6 錯題跨版本延續（第 4 個 commit；前提見盤點第 7 點）

**目標**：教師同步新版本後，題目還在且正解沒變的錯題紀錄（`n`、`at`、`ok`、`rm`）原樣帶到新版本；只有正解改變或被刪除的題目重置。

**同步時（伺服器，教師同步題庫的流程內）**
- 以題目 ID 比對舊版與新版，算出**丟棄清單** `drop`：
  - 新版本中不存在的題目 ID（被刪除）。
  - 正解改變：正解選項的文字（去除前後空白、合併連續空白後）不同，或選項數量改變，或題型改變。
  - 只改題幹、解析、錯字、干擾選項文字 → **不算改變**，延續。
- 寫入分類資料（首頁已讀取的那份 Unit 資料，不得增加讀取）：
  ```ts
  wrongCarry?: Record<newVersion, { from: oldVersion; drop: string[] }>;
  ```
  只保留最近 10 筆，超過的刪最舊的。
- **不得在同步時改寫任何學生的 progress**（避免一次同步產生全班寫入）。
- 同步畫面新增一個核取方塊「這次改版後，錯題全部重新計算」，**預設不勾**；勾選時該筆寫 `{ from: oldVersion, drop: '*' }`（或等效標記），表示不延續。用於教師大幅改寫題庫時。
- 同步完成訊息加一行：「錯題延續：保留 x 題的紀錄，重置 y 題（正解改變 a、刪除 b）」（題目數，非學生數）。

**讀取時（前後端共用的 `effectiveWrong`）**
- `wrong[目前版本]` 已存在 → 直接使用（代表已實體化，已含延續內容）。
- 不存在 → 沿 `wrongCarry` 從目前版本往回找：目前版本 → `from` → 再往前……，累積各段的 `drop`，直到找到有 `wrong` 資料的版本；把該版本的紀錄扣掉累積的 `drop` 後當作目前版本的錯題。
  - 鏈中斷（某版本沒有 `wrongCarry` 紀錄）或遇到 `'*'` → 視為沒有延續，錯題為空。
  - 1.7.0 以前發生過的同步沒有 `wrongCarry` 紀錄，**不追溯**。
- 伺服器寫入時（第 3.2 節）先把上述結果實體化到 `wrong[目前版本]`，再套用更新；舊版本的 `wrong` 資料保留不刪。
- 前端顯示與伺服器批改必須得到相同結果（同一個純函式、同一組測試）。

**複習考**：若盤點第 5 點顯示複習考有自己的版本與錯題，套用同樣規則；若複習考的錯題其實寫回來源分類，則自動適用，不需另做。

**教師端**：學生進度與匯出的錯題數一律經過 `effectiveWrong`。

## 4. 閃卡（取代作答型完整閃卡）

- **單元內**：整份。順序：今天剛錯 → 待複習 → 其他，各群內洗牌。**綜合練習**：10／20／30 張（見第 6 節）。
- **正面**：題幹＋選項（選項洗牌）。上方提示「先在心裡選好答案，再翻面」。學生**可以**先點一個選項當作自己的答案（只做標記，不送出、不記錄），也可以直接翻面。
- **翻面**（點卡片、「翻面」按鈕或空白鍵）：正解選項標綠並加「正解」字樣；若學生有先點選，標示「你選的是 B，正確」或「你選的是 B，正解是 D」；下方顯示解析（`QuestionContent.tsx`，學生看到的段落沿用現行規則）。
- 每張兩個按鈕：**「我會」**（下一張）、**「再看一次」**（排到本輪後段再出現一次）。
- 結束畫面：「看了 N 張，其中 M 張標記再看一次」＋「再翻一輪」「回到單元」；若本輪有「再看一次」，加「用抽題練習測一下」。
- **不呼叫 `submitAttempt`、不寫入任何資料**；「我會／再看一次」只存在本輪記憶體。
- 舊作答型閃卡取得的最高分保留（1.6.0 規則不變）。
- 後端相容：`submitAttempt` 若仍收到 `mode === 'flashcard'`（舊前端快取），照 1.6.0 處理（不更新最高分），錯題依第 3.2 節。

## 6. 綜合練習（`src/Student.tsx` 綜合練習卡）

### 6.1 練習範圍

```
練習範圍　已選 8 個分類・共 186 題（待複習 18、今天剛錯 5、未作答 61）　[全選] [全不選]

[■] 血液                      3 / 3 個分類 ▾
[▣] 心臟II                    4 / 6 個分類 ▴
     [✓] 心臟的電性活動    11 題・錯題 2・未作答 0
     [✓] 心電圖基礎         7 題・錯題 0・未作答 7
     [ ] 心輸出量的調節    11 題・錯題 0・未作答 11
[■] 淋巴系統                  1 / 1 個分類 ▾
```

- 候選分類**沿用盤點第 4 點的現行篩選，不可擴大或縮小**；複習考不列入。（若現行只含「目前學習」的單元，請在回報中標明，教師另行決定是否放寬。）
- 單元列依 `Unit.group` 分組（順序同首頁，無 group 歸「未分類」），三態核取方塊（`indeterminate`），勾單元＝全選／全不選其下分類；右側「已選 a / b 個分類」與展開箭頭；預設收合。
- 分類列：「n 題・錯題 k・未作答 m」。題數＝`Unit.questionCount`；錯題＝有效錯題數（經 `effectiveWrong`）；未作答＝`max(0, 題數 − 該分類 attempted 數)`。
- **預設全選**；「全選」「全不選」；摘要列即時更新。
- 記住選擇：`localStorage`，鍵含 courseId 與 uid，**存排除的分類 ID**（之後新增的分類預設包含）；讀寫包 try/catch，讀不到就全選；不存在或不再符合篩選的 ID 忽略。
- **不得新增 Firestore 讀取**：數字全部由首頁已讀的 `progress` 與課程資料計算。題庫只在按下練習後載入，且只載入已勾選的分類。

### 6.2 練習按鈕（全部不計分，不顯示「計分」組）

```
練習・不計分
閃卡　10 張  20 張  30 張
抽題　10  20  30  50
錯題複習（待複習 18 題）　10  20  全部 18 題
```

- **閃卡**：從範圍抽 N 張，順序：今天剛錯 → 待複習 → 未作答 → 其他，各群內洗牌；行為同第 4 節，不寫入。
- **抽題**：從範圍取題，順序：待複習 → 未作答 → 其他（今天剛錯歸「其他」）；錯題依第 3.2 節寫回各分類，`attempted` 寫回各分類。
- **錯題複習**：範圍內的待複習錯題，題數與排序同第 3.5 節（跨分類合併後排序）；依第 3.2 節寫回各分類。今天剛錯的提示與第 3.4 節相同。
- 停用規則：題數超過範圍合計的檔位停用；範圍合計 < 10 時，閃卡與抽題各改為「全部 X 張」「全部 X 題」；一個分類都沒勾時全部停用並提示「請至少勾選一個分類」。
- 結果頁：顯示各分類答對數與第 3.4 節的移除摘要。

### 6.3 後端
