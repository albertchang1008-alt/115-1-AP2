## 需修正的程式路徑

### D1 P1　刪除或另一筆確認先完成，被拒的匯入仍留成績明細

`functions/src/zuvioExams.ts:369–398` 在預檢後以獨立 `gen` 寫入學號、答案與分數。確認交易到 `:400–408` 才重新核對預覽及 revision。交易拒絕後缺少回收這一代明細的路徑。

可按以下順序核對：

1. 空場次 revision 為 0，確認 A 已通過預檢，暫停在寫入前。
2. 教師刪除成績，`:447–456` 將 `deletedRevision` 設為 1 並完成清理。
3. 繼續 A，`:389–398` 寫入 revision 1 的成績列。交易見預覽 revision 0 與目前 revision 1 不符而拒絕，這些儲存的原始成績列仍存在。若清理發生於 A 寫入之後，`:430–432` 的嚴格小於也會保留同為 revision 1 的成績列。
4. 兩次確認同時通過預檢而同取 revision 1 時，先提交的一次清理也只刪小於 1。另一次被拒的 `gen` 因而留下。現行報表依已提交的 `gen` 讀取（`:997–1000`），所以報表正確仍可能掩蓋殘留資料。

修正後，失效交易不可留下該次原始成績，且不得清到有效或其他待提交的代次。補「預檢後刪除」、「重複／同版並行確認」的確定性交錯測試，核對結果集合、預覽、有效成績和摘要。

`functions/tests/zuvio-ext.test.cjs:1188–1210` 在重送後以 `repA.analysis.items[0].p` 驗證，但此值可來自匯入時寫好的快取。補測也應比對有效 `gen` 的答案／分數與成績報表，並檢查結果集合中是否還有被拒的 `gen`。現有最後一個斷言只驗證有效代次的筆數。

### D1 P2　清理失敗時，已完成的匯入或刪除被顯示為失敗

`functions/src/zuvioExams.ts:400–425,446–457` 先提交成績指標與摘要、消耗預覽，或先清除成績指標，再等待交易外的 `cleanup`。若查詢或批次刪除失敗，例外會直接傳回教師。匯入已生效且同一預覽不可重試，刪除也已生效。補清理失敗的測試，使 callable 回覆與已提交狀態一致，並讓清理維持可恢復。

### V3 P2　切回原場次後，較早回覆可取代較新統計

`src/ClassroomInteraction.tsx:1101–1105,1182–1227,1237–1261` 以課程、考卷、場次 ID 比對回覆。這能擋 A → B，卻無法區分 A → B → A 中兩次選到 A。令首次 A 的結束後查詢先取得舊統計並延遲回覆，切 B 再切 A，讓第二次 A 的輪詢先返回新統計。後到的舊 A 回覆通過 `sameSelection`，`setLive` 和 `setMsg` 都會寫入目前畫面。修正須讓操作與輪詢回覆辨識各次選擇及較新讀取。新增測試須放行操作後續的統計請求，並核對往返切場後的數字與提示。

### V3 P2　新增場次的晚到回覆可混配考卷與場次

`src/ClassroomInteraction.tsx:1160–1178` 的新增場次回覆直接 `setSittingId(created.id)`。教師在 A 建立場次後可於回覆前切到 B（`:1235–1261` 的下拉仍可操作）。A 建立成功後仍保留選中的 B 考卷，卻寫入 A 的新場次 ID。教師面板會查詢不存在的 B／A 場次組合，開放鈕的判斷也只檢查兩個 ID 非空（`:1308–1309`）。場次建立與清單刷新也須遵守目前選擇，補延遲新增時切卷的回歸。
