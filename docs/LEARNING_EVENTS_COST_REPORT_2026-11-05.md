測試用真實教材 HTML、SDK 和 LearningBridge 在 390 寬 iframe 跑到完成。採固定動作、虛擬時鐘與固定亂數，包含腎小管教學答錯、提示及重試。AG 走查 22 分 27 秒，舊心臟走查 5 分 7 秒。Playwright 的父頁模擬接收呼叫並回覆 ID，捕獲的實際呼叫及時間再由兩版 Functions callable handler 寫進本機 Firestore 模擬器。只用合成課程、班級與身分。

### 防重、過渡與代價

- 一批至多 30 筆、請求事件 JSON 至多 20 KB。每份新批次保存 receivedAt、eventIds、typeCounts、events。已處理過的 ID 和本次成功寫入的 ID 都回 accepted。本批相同 ID 以第一筆為準。
- 診斷只留最近 600 個 ID，約涵蓋三次 190 事件的典型教材流程。UUID 內容約 22 KB，100 字元上限的 ID 內容約 60 KB。到達清單上限後，仍用一次 array-contains-any 查詢核對未命中的候選 ID。離線再久也可依保存的批次查到，不會因 600 筆淘汰就重算；依賴歷史批次繼續保留。
- 已有舊診斷時，用一次 document ID in 查詢確認仍在舊 events 的候選 ID，不逐筆讀。對於沒有近期欄位的既有診斷也查批次，防止舊 writer 曾覆寫診斷時遺失近期索引。舊診斷可比全新診斷每批多兩次空查詢最低讀取量，長時間使用達 600 筆的純新診斷則可能多一次。若切回舊版後端，舊程式不認識新 batches，跨版本重送有再次計入的風險。
- 使用統計保留舊 events 的事件粒度和原時間，新 batches 以接收時間每批一筆。正常寫入已防止兩來源落同一 ID。查詢範圍若已有重疊，優先保留舊 event，整批皆已出現則跳過，有新 ID 的批次仍只算一筆。兩來源共用 20,000 文件上限，只取時間與去重欄位。
- AG 使用紀錄範圍掃描剩舊版的 15.2%，沒有到一成。過渡期有舊資料的日期仍須讀舊 events，既存每日彙總照用。記錄數與熱度圖計數會隨粒度降低，教材診斷秒數、作答、提示與完成判定維持相同。
- 發布或封存課程最多延遲 1 分鐘反映到學習事件接收。停用名冊後，已通過的學生同一實例最多仍可寫 5 分鐘。每個呼叫仍驗證登入身分，快取命中不延長期限，未通過不快取。其他 access 呼叫維持即時讀取。
- 不需調整 Firestore 安全規則。讀寫透過 Functions Admin SDK，查詢使用既有的單欄索引能力。正式資料、8767 與 #6i 皆未操作。
