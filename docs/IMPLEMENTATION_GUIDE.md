# 課序 1.1.0 整合使用指南

## 教師流程

1. 新增課程：填名稱、固定代碼及學期，立即保存；不預填假班級。
2. 在課程內新增班級，填中文名稱及英數代碼；班級代碼只須在該課程內唯一。
3. 新增單元，代碼對應題庫分頁；各班勾選適用單元，另設必做、門檻、開放與期限。新增單元後檢查各班勾選。
4. 保存草稿，再在平台設定貼 Sheet 網址或 ID 並同步。同步只更新題庫草稿。
5. 預覽各班內容後發布。儲存草稿不改變學生當前權限；封存隱藏學生入口並保留紀錄。
6. 複製課程只帶單元與教材架構，名冊與題庫須重新同步；單元複製後同樣重新連接題庫。

## Google Sheet

使用 apps-script/CreateCourseTemplate.gs 的 createCoursePlatformTemplate() 建立一份全新的空白範本；記錄輸出的網址，分享給 Firebase 函式執行服務帳戶。此工具不負責同步，不需 Firebase 私鑰。

- 名冊：課程代碼、班級代碼、學號、姓名、學校信箱、啟用。信箱使用完整 @ctcn.edu.tw；同一學生可在不同課程出現，在一門課內只有一個目前班級。
- 題庫：分頁名稱為單元代碼；課程代碼、題目ID、題型、問題、選項A–D、解答、解析、核心概念、常見誤解、①先看題幹、②比較觀念、③推回答案、圖片網址。可另加講義標題、講義連結、補救資源；現有英文欄位及 A–H 相容。
- 題型為單選／圖片；圖片題要有 HTTPS 圖片。連續圖片題可沿用同課程同分頁的上一張圖，空白列或文字題會中斷沿用。
- 解答可用 A–H、1–8 或唯一匹配的選項文字。空白選項不會使答案代碼移位。
- 班級與單元必須先建立並保存；不同課程名冊分別回報結果，較早批次成功不因較晚批次失敗回滾。修正後可重試。
- 名冊缺列不自動刪除；請用啟用 FALSE 停用。Sheet 是主要維護來源，後台直接更改後應同步修正 Sheet，避免下次同步還原。

## 舊名冊轉換

舊課程仍可讀取原名冊。教師到班級名冊按「預覽舊名冊轉換」，檢查人數及前 20 筆，再按確認，才寫入新課程歸屬。原資料不刪除；已轉換項目不重複覆蓋。單一舊班超過 1000 人或單次超過 3000 人需先另行整理。

新名冊使用 enrollments/{courseId}__{email}，學號唯一對應放在 courses/{courseId}/studentIds；不再用全平台班級判斷新課程權限。

## 互動教材

一般 HTML 使用閱讀確認；要紀錄闖關與診斷，教材必須加入公開 SDK：

```html
<script src="https://你的教材站/course-learning.js"></script>
```

檔案位於 public/materials/course-learning.js，可與教材一起部署。各互動觸發點呼叫：

```javascript
CourseLearning.explore('stomach');
CourseLearning.answer('stage1', true); // 每次回答都呼叫，錯誤時傳 false
CourseLearning.hint('stage1');
CourseLearning.complete(); // 保留教材原有的星星／徽章／破關畫面
```

後台活動類型選 HTML，紀錄方式選「闖關與學習診斷」，設定教材版本及實際節點、題目總數。ID 只使用英數字、-、_。

SDK 接收平台 init，以 activityId、版本、sessionId 回報；平台驗證來源與登入權限。事件 ID 去重、每批最多 30 筆；離線資料暫存於此學生的瀏覽器，重新開啟同教材會補送。前景閒置超過 60 秒不累計新時間。未通關也保存歷程，首次答案在同教材版本下不會被重玩覆寫。

教材需要允許 iframe 嵌入。普通外部網站不會自動產生細部互動事件。資料是練習診斷，客戶端仍可被修改，不作防作弊證據。

GA4 為未設定的選配；教師日常查看 Firestore 的班級分布與個人明細，不需要 GA4。

## YouTube 與色系

YouTube 標為選看，只保留續播與參考觀看紀錄，不納入達標分數、完成度或診斷指標。未觀看或無法嵌入都不影響學習流程。

右下角色系選擇提供藍、綠、紫與夜間模式；記住此瀏覽器偏好。題目圖片不變色。

## 上線順序

本機檢查通過後，先部署 Firebase 函式與索引，再發布 GitHub Pages。新 UI 需要新版函式；不要只更新前端。正式名冊轉換由教師先預覽再確認。此指南不代表已完成正式部署。
