# NotebookLM 互動教材：初稿到正式發布流程

## 原則

NotebookLM 負責依指定來源整理**正確、可讀的內容初稿**；課程平台負責把初稿修飾為可教學、可操作、可診斷、可發布的教材。NotebookLM 產生的 HTML 不直接放上正式網址，也不直接視為已完成教材。

```text
教師指定章節與學習目標
  → NotebookLM 單檔內容初稿
  → 本地審稿與知識校對
  → 圖像／互動／手機體驗修飾
  → 平台事件與題目診斷串接
  → 驗收、版控、發布
```

## 0. 教師先填的教材規格

在送 NotebookLM 前，教師先決定以下資料；未定義就不進入正式製作。

| 項目 | 範例 |
| --- | --- |
| 來源章節 | 心動週期 |
| 教材代號（slug） | `cardiac-cycle`，正式版本資料夾 `cardiac-cycle-v2` |
| 學習目標 | 說出心動週期各時相的瓣膜狀態；分辨 S1、S2；計算心搏量與心輸出量 |
| 知識節點 | 預設 6 個；教師可依章節指定（例如心臟的電性活動 9 個） |
| 題目 | 第一關先備知識 6 題＋第二關生活情境應用 5 題＝11 題 |
| 病理／藥理例外 | 預設不寫；要保留的內容逐項列出（例如止血機制的阿斯匹靈、華法林） |

教材版本一經發布不回頭覆寫；內容大改時建立 `-v2`，保留舊版診斷資料。

## 1. 交給 NotebookLM 的「內容初稿」提示詞

2026-09-25 依心臟與血液教材的入門化修訂重寫：對象為第一次學解剖生理的五專生、不寫病理藥理、節點數由教師指定（預設 6）、固定 6＋5 題、第二關改為生活情境，並要求同時輸出題庫表（可直接貼進 Google Sheet 題庫的前段與①～④欄）。這個階段仍刻意**不要求** CourseLearning、GA4 或 Firestore，避免模型自行杜撰串接程式。將【】內替換後使用。

```text
請依目前勾選的來源，製作「【章節名稱】」的單一檔案互動資訊圖表 HTML 初稿。

【對象與程度】
- 對象是第一次學解剖生理學的五專一年級學生，還沒學過病理學與藥理學。
- 只寫正常構造與生理機制。不要出現疾病名稱、症狀、檢查、藥物、治療或病例；
  例外只有我在這裡列出的項目：【無，或列出要保留的內容】。
- 用詞淺白，一句話只講一件事；專有名詞第一次出現時附英文。
- 同一個數值在整份教材只用一種寫法，前後一致（例如「約 70~80%」不要另一處寫「70%」）。

【版面結構（由上到下）】
1. 標題、一行副標、4 個重點數字卡。
2. 情境實驗室：一張可切換 2~4 個狀態的主圖（內嵌 SVG），每個狀態附一句說明；
   下方一題「先猜一猜」預測題，選完立即回饋。
3. 知識節點：剛好【節點數，預設 6】個，依學習順序排列，可依 2~3 個分類篩選。每個節點包含：
   - 標題、一句核心概念、最多 3 個重點；
   - 一張說明關係的內嵌 SVG 示意圖（箭頭、中文標示、手機可讀，每張圖要各自不同）；
   - 一個補充框，標題只能用「生理重點」「生活連結」「實驗課觀察」「模型觀察」其中之一，不可用「臨床」。
4. 兩關隨堂診斷：
   - 第一關｜先備知識：6 題，逐題作答，答對才能到下一題。
   - 第二關｜生活情境應用：5 題，題目順序與選項每輪重新洗牌，5 題全對才算通關；答錯可整輪重來。

【出題規則（11 題都適用）】
- 題幹 40 字以內，一題只考一個概念；答案一定能在某個知識節點裡找到。
- 4 個選項、唯一正解；干擾選項要同類、看起來合理，不用「以上皆是／皆非」，不出現重複選項。
- 題幹前不要加題號（題目會洗牌）；解析不寫「答案是 B」，要寫選項內容。
- 第二關題幹以【生活情境】【實驗觀察】【模型觀察】【生理判讀】其中之一開頭，
  情境取材自日常生活、運動、實驗課或心臟／骨骼等模型，不用醫院、患者或年齡病例。
- 每題附：提示（答錯時顯示，指出思考方向但不直接給答案，約 25 字）、
  解析（正解理由，並說明一個最容易混淆的選項，約 50 字）。提示與解析開頭不要加「提示：」「解析：」。

【固定 ID（不可更改）】
- 教材代號：【slug，例如 cardiac-cycle】
- 知識節點：data-node-id="【slug】-node-01" 起依序編號到最後一個節點
- 第一關題目：【slug】-foundation-q01 ~ q06
- 第二關題目：【slug】-case-q01 ~ q05

【技術規格】
- 只用原生 HTML、CSS、JavaScript，全部寫在同一個檔案；圖用內嵌 SVG，不用外部圖片、字型或 CDN。
- 所有可點的東西都是原生 <button>，以 addEventListener 綁定；展開控制附 aria-expanded、aria-controls。
- 手機 360px 寬可用，不得出現橫向捲動；SVG 在窄螢幕不可裁切文字。
- 通過／未通過的結果訊息預設隱藏，只在作答結束時顯示。
- 這是內容初稿：不要加入 Google Analytics、Firebase、登入、學生資料、postMessage 或任何追蹤程式。

【輸出】
1. 先輸出完整可執行的 HTML（從 <!DOCTYPE html> 到 </html>），前後不要加任何說明文字。
2. HTML 之後，另外輸出一個表格，列出 11 題，欄位依序為：
   題目ID｜問題｜選項A｜選項B｜選項C｜選項D｜正確答案代碼｜解析｜①先想關鍵字｜②提問鏈｜③回頭選答案｜④一句話記憶
   - ①先想關鍵字：題幹中該先抓的詞，約 40 字
   - ②提問鏈：2~3 個一步步推論的小問題，約 100 字
   - ③回頭選答案：用正確選項的內容說明結論，約 30 字
   - ④一句話記憶：一句好記的重點，約 50 字
```

## 2. 初稿進入本平台後的修飾工作

| 階段 | 這裡要完成的工作 | 通過條件 |
| --- | --- | --- |
| A. 內容校對 | 核對來源、術語、數值、因果順序與題目唯一正解；清除重複選項 | 教師確認可教、可考 |
| B. 視覺教學化 | 把「圖解需求」實作為 SVG、教師提供圖檔或有授權圖片；加入圖例、箭頭與臨床連結 | 圖能獨立傳達關係，不靠大段文字猜意思 |
| C. 互動可用性 | 展開控制改為唯一真實按鈕；處理 `aria-expanded`、焦點、鍵盤、篩選與手機版 | 點提示文字、Enter、Space 都能正確展開／收合 |
| D. 平台診斷 | 載入 `course-learning.js`；設定固定節點與題目 ID；串接探索、有效停留、每題作答與完成事件 | 不傳姓名、信箱、學號或登入資訊 |
| E. 闖關規則 | 題目順序／選項洗牌；每題顯示解析；一輪全對才完成，重做不覆寫首次診斷 | 少一題或非滿分不送 completed |
| F. 發布驗收 | 放進 `public/materials/<版本>/index.html`、教師後台活動設定、iframe 真實帳號測試 | 事件 ACK、教師診斷與手機版都正常 |

## 3. 平台串接時的固定規則

正式版才加入：

```html
<script src="https://albertchang1008-alt.github.io/115-1-AP2/materials/course-learning.js"></script>
```

| 學習行為 | 正式教材呼叫 | 限制 |
| --- | --- | --- |
| 第一次展開節點 | `CourseLearning.explore(nodeId)` | 每節點一次 |
| 前景中的節點閱讀 | `CourseLearning.nodeTime(nodeId, seconds)` | 僅有效前景時間；單批 1–60 秒 |
| 每題選答 | `CourseLearning.answer(questionId, correct)` | 題目 ID 固定；保留首次結果與作答事件 |
| 全題答完且全對 | `CourseLearning.complete()` | 每個教材活動一次 |

GA4 如日後啟用，只送去識別的教材事件；不得送學生可識別資訊，也不可用行為資料自動標籤學生「猜題」或「認真」。

## 4. 每份教材的交付物

1. `html/<教材名稱>.html`：NotebookLM 初稿與教師審稿版本。
2. `public/materials/<material-version>/index.html`：通過平台驗收的正式版本。
3. 教師活動設定紀錄：網址、教材版本、探索節點分母、題目分母與完成規則。
4. 版本變更摘要：內容、題目、圖像或診斷邏輯有何改動。

## 5. 發布前最小驗收清單

- [ ] 圖解可在手機寬度閱讀，且不只是裝飾。
- [ ] 每個看似可點的控制都是實際可點的 `<button>`。
- [ ] 六個（或規格指定數量）節點與題目 ID 均固定且不重複。
- [ ] 重開節點不重複送探索；重答不覆寫首次診斷。
- [ ] 非滿分不送完成事件；全對才通關。
- [ ] iframe、重新整理、離線後恢復連線、手機寬度各驗證一次。
- [ ] 真實學生資料只留在授權的平台診斷；GA4 不收個資。
