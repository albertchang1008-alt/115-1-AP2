## 4. 教師後台：學習進度看板

### 4.1 位置
教師後台新增 tab「學習進度」（沿用 `location.hash` 切 tab）。建議新元件 `src/ProgressBoard.tsx`。

### 4.2 區域與逐班開放的關係

| 區域值 | 後台欄名 | 學生端 |
|---|---|---|
| `hidden` | 尚未開放 | 看不到，後端不回傳 |
| `current` | 目前學習 | 首頁最上方 |
| `archived` | 已考完 | 首頁底部收合區，依歷史標籤分組；閱讀、作答、練習照常可用 |

- **看板以全課程為單位控制**，所有班級共用同一個區域設定。
- 既有逐班開放保留。學生看得到某次單元的條件：**該班有勾選 AND `visibility !== 'hidden'`**。
- 實作方式：在 `forClass()` 內加入 `hidden` 過濾，讓所有既有後端防線自動生效。
- 看板上若某次單元未被任何班級勾選，列上顯示「沒有班級開放」提示，但不阻擋移動。

### 4.3 版面
- 桌機三欄；手機與平板改為垂直區塊或以區域為分頁。
- 每欄依單元（group）分組，可展開看次單元。
- 次單元列：名稱、題數、所屬單元、開放班級數、（已考完者）歷史標籤。
- 同一單元的次單元分散在不同區時，標題旁顯示「部分在其他區」。

### 4.4 操作

**移動**
- 以單元為單位移動（該欄內此單元的所有次單元），或展開後單獨移動次單元。
- 每列「移到…」選單為必做；桌機拖曳為加分項，不得為此新增套件。
- 勾選框批次移動。

**移到「已考完」**
- 小視窗：歷史標籤輸入框（選填，trim，最長 30 字，下方列出既有標籤可點選），按鈕「確定」「略過標籤」。

**本次考試結束**（「目前學習」欄上方按鈕）
1. 確認視窗列出將移動的全部次單元（依單元分組）。
2. 同視窗內歷史標籤輸入框（選填）。
3. 送出後所有 `current` 改為 `archived`，共用標籤與 `archivedAt`。
4. 詢問「要從尚未開放選擇下一批單元嗎？」→ 開啟 `hidden` 勾選清單，確認後移入 `current`；可關閉略過。

**歷史標籤管理**：可修改單一次單元標籤，或整批改名。

**學生首頁提示文字**：看板頂部輸入框 `course.studentNotice`（選填，最長 60 字），空白則學生端不顯示。

### 4.5 防呆

| 情況 | 行為 |
|---|---|
| `current` 為空 | 看板頂部警示「目前沒有開放中的單元，學生首頁會是空的」 |
| 有新同步的 `hidden` 次單元 | 看板頂部「有 N 個新同步的次單元尚未開放」，點擊捲到該處 |
| 從 `current`／`archived` 移回 `hidden` | 確認：「學生將看不到這 N 個次單元，作答紀錄與成績會保留，教師報表照常顯示。」 |
| 從 `archived` 移回 `current` | 直接移動，清除 `archiveLabel`、`archivedAt` |
| 儲存失敗 | 顯示錯誤並還原畫面，不做靜默失敗的樂觀更新 |

### 4.6 學生視角預覽
看板右上角「預覽學生首頁」：先選一個班級，以唯讀模式渲染學生首頁元件（第 5.1 節），套用該班逐班開放與目前區域。沒有學生進度，所有活動顯示「未開始」，並標示「預覽不含學生進度」。重用學生首頁元件並傳入 `preview` 旗標，停用導航與作答。

### 4.7 教師課程設定頁依單元分組（1.2.0 補完）
`src/CourseSetup.tsx` 的次單元列表依 `group` 分組並可折疊；沒有 `group` 的歸「未分類」。不改變既有設定欄位與儲存行為。

## 5. 學生端

### 5.0 共通
- 手機優先；寬度 < 768px 一律單欄。
- 色系、字級收進右上角「顯示設定」按鈕（`aria-label`），點擊後從底部滑出面板，沿用既有儲存方式。
- 觸控目標 ≥ 44px；使用真正的 `<button>`／`<a>`。
- 底部固定按鈕加 `env(safe-area-inset-bottom)`。
- 字級「大」時不得截斷或重疊。

**路由（hash route）**

| 畫面 | 路由 |
|---|---|
| 課程首頁 | `#/course/<courseId>` |
| 次單元頁 | `#/course/<courseId>/unit/<unitId>?tab=pre\|class\|post\|practice` |
| 閱讀（互動教材、YouTube、外部連結） | `#/course/<courseId>/unit/<unitId>/activity/<activityId>` |
| 完整測驗、抽題 | `#/course/<courseId>/unit/<unitId>/quiz?mode=full\|draw&n=10` |
| 完整閃卡 | `#/course/<courseId>/unit/<unitId>/flashcard` |
| 錯題複習 | `#/course/<courseId>/unit/<unitId>/review` |

- ID 一律 `encodeURIComponent`。
- 路由只決定畫面，資料存取仍由後端驗證名冊、逐班開放與區域，不信任 URL。
- 直接開啟無權限或 `hidden` 次單元的路由時，導回課程首頁並顯示「此單元目前未開放」。
- 瀏覽器返回鍵要能在畫面間正常返回。

### 5.1 首頁（課程）
**排列原則：待辦在上、單元列表在下。** 學生一進來不必捲動、不必點開就知道哪裡還沒做。

由上到下：
1. 頂部列：返回課程列表（若有）、顯示設定。
2. 學期與課程名稱、`studentNotice`（有值才顯示）。
3. **總進度一行**：「目前學習：已完成 3 / 8 個必做次單元」＋細進度條。不佔大面積。
4. **還沒完成**（第 5.5.4 節）：預設展開，位於第一屏；全部完成時改顯示「目前學習的內容都完成了」，並在該區顯示綜合練習與錯題入口。
5. **建議複習：錯題**（第 5.7 節）：標題「建議複習｜錯題 12 題」，底下依次單元列出「次單元名　N 題」，點擊直接進入該次單元的錯題複習。無錯題時整區隱藏。
6. **綜合練習**（第 5.6 節）：卡片內選題數，按鈕直接開始。
7. **目前學習**：`current` 次單元依單元分組、分組內依既有排序。
   - 單元標題：「2 / 3 個次單元完成」。
   - 次單元卡片：名稱、完成狀態、「必做活動 2 / 4」、最高有效成績／達標門檻、到期日（沿用既有逾期提示）。
8. `current` 為空：「老師尚未開放新的單元」，並隱藏綜合練習卡。
9. **已考完的單元**：預設收合，標題帶數量，例如「已考完的單元（12）」。
   - 收合時若有未完成的必做次單元，標題旁顯示「3 個未完成」。
   - 展開後依 `archiveLabel` 分組，組順序依組內最新 `archivedAt` 由新到舊；每組顯示完成數。
   - 未填標籤歸「其他」，組內依 `archivedAt` 由新到舊。
   - 組內再依單元分組，完成狀態顯示同目前學習；各次單元的完整測驗、閃卡、抽題、錯題複習照常可用。
10. 第 4、5、6 區只涵蓋 `current` 次單元；`archived` 的未完成項目與錯題只在第 9 區內各次單元中呈現。
11. 學習紀錄入口不受區域限制；`hidden` 次單元的紀錄**不在學生端顯示**（資料保留，教師報表照常）。`getProgress`、`getHistory` 需在後端過濾 `hidden` 次單元。

### 5.2 次單元頁：分頁標籤
- 頂部：返回首頁、單元名／次單元名（不重複同一詞）、顯示設定。
- **成績進度卡**：最高有效成績、達標門檻、進度條、「還差 N 分達標」或「已達標」。
- **完成進度**：「必做活動 2 / 4 完成」＋進度條。
- 標籤列（`role="tablist"`，鍵盤左右切換）：課前｜課堂｜課後｜練習，對應既有四個分區。
  - 有必做活動：顯示「1 待完成」或「✓ 完成」（SVG 圖示＋文字）。
  - 只有非必做活動：顯示活動數。
  - 沒有活動：「暫無」，對比仍 ≥ 4.5:1。
  - 預設開啟第一個有未完成必做活動的標籤；都完成則開啟第一個有內容的標籤。
  - `tab` 寫入路由，返回時維持。
  - 空標籤內容：「本單元暫無課前內容」等。
- **切換標籤只做前端顯示，不得重新讀取題庫或教材。**

**活動卡片**
- 圖示依類型區分：互動教材、YouTube、外部連結、完整測驗、完整閃卡、抽題、錯題複習。
- 右上標籤由活動類型推導：

| 活動 | 標籤 | 計入完成 |
|---|---|---|
| 完整測驗 | 計入成績 | 是（透過達標） |
| 完整閃卡 | 計入成績 | 是（透過達標） |
| 互動教材／資訊圖卡 | 必做 | 是 |
| 外部連結 | 必做 | 是 |
| YouTube | 選看 | 否 |
| 抽題練習、錯題閃卡 | 僅供練習 | 否 |

- 卡片副標顯示實際描述；與標題相同時不顯示。
- 活動維持教師設定順序，不依完成狀態重排。
- 狀態與按鈕：

| 活動 | 狀態 | 按鈕 |
|---|---|---|
| 互動教材 | 未開始／已完成（學生端無法取得教材內部進度，不顯示進行中） | 開始／再看一次 |
| 外部連結 | 未讀／已確認閱讀 | 開啟 |
| YouTube | 未看／看過部分／看完 | 觀看／繼續 |
| 完整測驗、完整閃卡 | 未作答／已作答・N 分未達標／已達標 | 開始／再做一次 |
| 抽題、錯題閃卡 | 抽題顯示「已練習 N 次」或「尚未練習」；錯題閃卡顯示錯題數與時間範圍選單，0 題時停用並顯示「目前沒有錯題」 | 開始 |

**練習標籤內容**：完整測驗、完整閃卡、隨機抽題（10／20／30 分段按鈕，沿用 1.2.0 規則）、錯題閃卡（含時間範圍選單，見第 5.7 節）。綜合練習只在首頁，不在次單元頁；錯題複習作答模式已移除。

### 5.3 全螢幕作答
- 出題邏輯完全沿用現有程式（含未作答優先、完整作答題數驗證），只替換外層呈現。
- 版面：頂部列（✕ 離開、測驗名稱、題號 `3 / 10`、進度條）；一次一題；題幹粗體、選項一般字重、整列可點、最小 56px、`role="radio"`；底部固定主要按鈕。
- 完整閃卡沿用既有閃卡互動，只改為全螢幕外框、頂部列與離開確認。
- **回饋時機**：

| 模式 | 流程 |
|---|---|
| 完整測驗、完整閃卡 | 作答中不揭曉；交卷後成績摘要才顯示正解與依據 |
| 抽題、綜合練習 | 選擇 →「送出答案」→ 顯示對錯與依據、鎖定選項 →「下一題」／「查看結果」 |

  依據使用 `QuestionContent.tsx`（學生只看①～④）。抽題與錯題的逐題回饋直接使用前端已取得的題目正解。
  **答案鍵政策（教師決策）**：`getBank` 回傳含正解的題目維持現狀，教師已知悉並接受學生可能從前端取得答案鍵；但**分數必須由後端批改**，見第 7.7 節。
- **離開確認**：✕、手機返回鍵、瀏覽器返回（hash 變更）時跳出底部確認：「作答尚未完成，確定離開？離開後本次作答不會保存。」按鈕「繼續作答」「離開」。交卷後不需確認。可加 `beforeunload`。
- **成績摘要**：分數、答對 N / 總題數、達標狀態。完整測驗與完整閃卡註明「最高有效成績取歷次最高分」；抽題與錯題註明「本次為練習，不影響成績與完成度」。按鈕：「複習錯題」（無錯題隱藏）、「再做一次」、「回到單元」（返回原標籤）。

### 5.4 資訊圖卡全螢幕閱讀
- 互動教材點擊後進入閱讀路由，**不再在單元頁內嵌 iframe**。YouTube 沿用同一個閱讀頁外框。**外部連結維持既有的開新分頁方式**，不嵌入；點擊外部連結卡片進入閱讀路由時，頁面只顯示標題、說明、「開啟連結」按鈕與「確認已閱讀」按鈕。
- 版面：
  - 頂部列約 48px：返回（`aria-label="離開閱讀"`）、標題、全螢幕按鈕。
  - 框架高度 `calc(100dvh - 頂部列)`（附 `100vh` 後備），寬度 100%，外層不捲動。
  - 頂部列常駐 48px。自動收起僅在能可靠取得捲動訊號時實作，否則不做。
  - 不鎖定方向，支援橫向。
  - iframe 既有 `sandbox`、來源限制、`postMessage` 來源檢查保留；加 `allow="fullscreen"`。
- 全螢幕按鈕：特性偵測 `document.fullscreenEnabled` 與 `requestFullscreen`，不支援則隱藏。進入全螢幕的對象是閱讀頁容器。
- 平台層事件：既有 `LearningEvent` 沒有進入、離開閱讀頁與 `visibilitychange` 類型，**本版不送、不擴充 schema**。閱讀時間仍以圖卡依規範回報的事件為準。
- 顯示設定（色系、字級）：`docs/INFOGRAPHIC_SPEC.md` 未定義此訊息，本版**不送**。
- 平台頂部列負責離開；圖卡內按鈕由圖卡自行處理。
- 教材送出 `completed` 後，返回次單元頁時狀態立即更新為已完成。

### 5.5 完成度規則與完成狀態

#### 5.5.1 新的次單元完成規則（教師決策）
**必做次單元的完成條件改為以下全部成立：**
1. 有題庫者：`best >= threshold`（既有規則不變；`best` 由完整測驗或完整閃卡更新）。
2. 該次單元（學生可見範圍內）的每一個**互動教材**活動都已收到 `completed`。
3. 該次單元的每一個**外部連結**活動都已「確認已閱讀」。

補充：
- YouTube、抽題、錯題複習不計入。
- 沒有題庫的次單元：只看條件 2、3；若也沒有互動教材與外部連結，則不計入完成度分母，學生端顯示「僅有選看或練習活動」。
- 非必做次單元：沿用既有規則不計入課程完成度，但學生端仍顯示其活動與次單元的完成狀態。
- **修改位置：`shared/model.ts` 的既有完成度函式。** 教師報表、完成度、結算、學生端全部共用同一函式，確保一致。
- 結算快照的處理見第 7.6 節（快照記錄規則版本，舊快照沿用舊規則）。
- 學期初尚無學生資料，不需要資料遷移。

#### 5.5.2 各層彙總

| 層級 | 顯示 | 規則 |
|---|---|---|
| 活動 | 第 5.2 節狀態表 | — |
| 標籤 | 「N 待完成」／「✓ 完成」 | 標籤內必做活動（互動教材、外部連結、以及完整測驗或閃卡未達標時計為 1 項） |
| 次單元 | 未開始／進行中（2 / 4）／已完成 | 5.5.1；已完成＝全部條件成立；至少一項有進度＝進行中 |
| 單元（group） | 「2 / 3 個次單元完成」 | 同組、同區域、計入分母者 |
| 首頁目前學習 | 「已完成 3 / 8 個必做次單元」 | `current` 必做次單元 |
| 首頁歷史區 | 收合時「N 個未完成」；展開後每組完成數 | `archived` 必做次單元 |

「必做活動 X / Y」的 Y＝互動教材數＋外部連結數＋（有題庫則 1，代表達標）。

#### 5.5.3 視覺
- 狀態一律 SVG 圖示＋文字，不只靠顏色。未開始＝空心圓、進行中＝半實心圓、已完成＝圓內打勾；「已達標」用文字徽章。
- 各色系下文字對比 ≥ 4.5:1、圖示 ≥ 3:1。
- 完整 `aria-label`，例如「血液組成互動教材，必做，進行中」。

#### 5.5.4 首頁「還沒完成」清單
- 內容：`current` 必做次單元中未完成的項目，每列「項目｜單元／次單元｜所在標籤」，點擊直接進入活動（互動教材進閱讀頁、外部連結進閱讀頁、未達標者進次單元頁練習標籤）。
- 未達標項目文字：「完整測驗未達標（80 / 100 分）」。
- 排序：首頁單元與次單元順序 → 標籤順序（課前、課堂、課後、練習）→ 教師設定的活動順序。
- 超過 5 項顯示前 5 項，下方「查看全部 N 項」。
- `archived` 的未完成項目不列入，只在歷史區標題顯示數量。

#### 5.5.5 資料與效能
- 由學生已取得的 `bootstrap`、`getProgress` 資料計算，不為每個活動額外呼叫或讀取。
- 資料不足時，優先在既有 `bootstrap` 或 `getProgress` 回應中加入每個次單元的完成摘要（由共用函式計算），不要讓前端多次呼叫。
- 從作答或閱讀返回時，使用交卷、`saveActivity`、`saveLearningEvents` 回應後的狀態即時更新，不需學生重新整理。

### 5.6 綜合練習（仿 v1.9）

**定位**：跨次單元的混合練習，永遠不計成績、不計完成度，與 v1.9 的「綜合練習」一致。

- **位置**：首頁（跨次單元，不放在次單元頁）。
- **範圍固定為 `current` 的全部次單元**；`archived`、`hidden` 一律不納入。教師按「本次考試結束」後，範圍自動換成下一批，不需要學生或教師操作。
- **卡片內容**：標題「綜合練習」、說明「跨單元混合出題，不計成績」、題數分段按鈕 10／20／30／50（範圍內總題數不足的檔位停用）、「開始練習」。
- **出題排序**：合併範圍內所有次單元的題目後，依 **錯題 → 未考過 → 其他** 三群排序，各群內洗牌，再取所選題數。錯題優先是為了讓綜合練習能補救錯題（錯題閃卡不作答，不會移除錯題）。
- **作答**：使用全螢幕作答外框，逐題回饋，與抽題練習一致。路由 `#/course/<courseId>/mixed?n=20`。
- **交卷後**：
  - 不更新 `best`、不影響完成度、不寫入「必做」相關狀態。
  - **答錯的題目寫回各自次單元的錯題清單；出現過的題目寫回各自次單元的 `attempted`。** 因此綜合練習之後仍可用錯題複習補救。
  - 成績摘要顯示答對數與各次單元的錯題數，並提供「錯題閃卡」入口。
- **實作注意**：題目來自多個次單元，交卷寫入必須依次單元分組。可沿用既有交卷入口分次寫入，或新增專用入口；請選擇讀寫次數較低的做法並在回報中說明。
- **載入量**：範圍內每個次單元的題庫都要取得，第一次可能較重（有前端快取後只發生一次）。請在盤點中給出範圍內次單元數與總題數的實際上限建議；若超過建議值，卡片顯示提示並限制可選題數，不要靜默變慢。

### 5.7 錯題清單與錯題閃卡

#### 5.7.1 目前的問題
錯題清單只記「曾經答錯的題目 ID」，沒有時間與次數，學生無法針對最近錯的或一直錯的題目複習。

#### 5.7.2 紀錄與更新
- 錯題紀錄改為記錄**答錯次數**與**最後答錯時間**（資料結構見第 7.8 節）。
- **會改變錯題清單的只有作答模式**：完整測驗、完整閃卡、抽題練習、綜合練習。答對即移除該題；答錯則 `n + 1`、更新 `at`。
- **錯題閃卡不改變錯題清單**（沒有作答，不能當作學會的證據）。此規則要顯示在畫面上：「閃卡不會改變錯題清單，在測驗或練習中答對才會移除」。
- 錯題仍以次單元與題庫版本為單位（既有設計）。題庫改版後該次單元錯題清單重置，此行為不變，錯題區需顯示一行說明：「題目更新後，錯題會重新計算」。
- **本版不再有 `mode=review` 的作答模式**，相關路由、UI 與邏輯一併移除（若既有程式已有錯題複習作答模式，改為不再提供入口；後端既有處理可保留但不得在學生端出現）。

#### 5.7.3 錯題閃卡（仿 v1.9）
- 路由：`#/course/<courseId>/unit/<unitId>/wrongcards?range=24h|7d|all`
- 全螢幕外框，與閱讀、作答一致（頂部列、離開、安全區）。
- **互動**：一次一張。正面題目，點擊或按鈕翻面後顯示正解與解析（沿用 `QuestionContent.tsx`，學生只看①～④）。
- **不作答、不判定對錯、不計分、不更新 `best`、不計完成度、不寫入 `attempted`、不改變錯題清單。**
- 每張卡有兩個動作：
  - **我會**：翻下一張。
  - **再看一次**：把該題排到本輪後段，稍後再出現一次。
- 本輪結束畫面：「本次看了 N 張，其中 M 張標記再看一次」，並提供「再翻一輪」「做綜合練習」「回到單元」。
- **「我會／再看一次」只在本輪有效，不寫入後端**，不增加任何讀寫。
- 沒有錯題時不提供入口（卡片停用並顯示「目前沒有錯題」）。

#### 5.7.4 時間範圍（採 v1.9 概念，選項調整）
- 選項固定三個：**最近 24 小時／最近 7 天／全部**，依「最後答錯時間」相對**現在**判定。
- **預設「最近 7 天」**；該範圍 0 題時自動改選「全部」。
- **每個選項旁直接顯示題數**，例如「最近 7 天（14 題）」。題數由學生端已取得的進度資料即時計算，**不得為此新增任何後端呼叫或讀取**。
- 0 題的選項停用並顯示「這段期間沒有錯題」。
- 時間範圍只作用於錯題閃卡，不影響完整測驗、完整閃卡、抽題與綜合練習。UI 上必須放在錯題卡片之內，不可與其他選項並排。
- 舊資料（`at: 0`，見第 7.8 節）只在「全部」出現。
- **卡片順序**：範圍內依答錯次數由多到少，次數相同時依最後答錯時間由新到舊。

#### 5.7.5 入口（三處一致）
1. **首頁錯題卡**：標題「建議複習｜錯題 N 題」，依次單元列出題數，點擊進入該次單元的錯題閃卡；卡片內含時間範圍選單。
2. **次單元頁練習分頁**：錯題閃卡卡片，含時間範圍選單與題數。
3. **成績摘要頁**（對應 v1.9 結果頁的複習入口）：交卷後提供「錯題閃卡」與「綜合練習」，**不使用遮住成績的對話框**，分數須可見。

## 6. 事件錯誤修正

**原因**：`public/materials/course-learning.js` 的 `node_time` 先 `Math.floor(seconds)` 再送出，停留 0.1–0.999 秒時送出 `seconds: 0`，被前端 `src/LearningBridge.ts` 與後端 `shared/learning.ts` 的 `seconds > 0` 拒絕。最常由 `trackScrollNodes()` 在快速捲動時觸發。

**修正**
1. SDK：先取整，取整後仍 `> 0` 才送出；為 0 則不送。
2. 驗證規則維持 `seconds > 0`，不放寬。
3. 檢查其他教材自行送出停留事件的程式是否有同樣問題，列出但不修改教材檔案（`public/materials/course-learning.js` 是平台 SDK，可修改）。
4. 前台錯誤顯示：驗證失敗寫入開發模式 console 與既有後端錯誤紀錄；學生端最多顯示「學習紀錄暫時無法儲存」，同一次閱讀只顯示一次。
5. 測試：0.5 秒不送出、1.2 秒送出 1、驗證拒絕 0 與負數、被拒時不拋出未處理例外。

## 7. 資料、後端、同步

### 7.1 資料模型（`shared/model.ts`）

```ts
type UnitVisibility = 'hidden' | 'current' | 'archived';

interface Unit {
  // ...既有欄位（含 group?: string）
  visibility?: UnitVisibility;   // 缺值視為 'current'
  archiveLabel?: string;         // trim 後 1–30 字；僅 archived
  archivedAt?: number;           // ms；僅 archived
  visibilityUpdatedAt?: number;  // ms
}

interface Course {
  // ...既有欄位
  studentNotice?: string;        // trim 後 0–60 字
}

// 錯題紀錄（第 7.8 節）
interface WrongEntry { n: number; at: number; }   // 答錯次數、最後答錯時間（ms）
// progress.units[unitId].wrong: Record<version, Record<questionId, WrongEntry>>
```

- 區域存在次單元上；「以單元移動」是前端批次操作，不存單元層級狀態。
- `archiveLabel` 不過 `safeCode`；trim、去除控制字元、限制長度。
- `Unit` 內嵌於課程的 `draft` 與 `published`，學生只讀 `published`。**區域相關欄位（`visibility`、`archiveLabel`、`archivedAt`、`visibilityUpdatedAt`）與 `studentNotice` 由專用函式在同一個 transaction 內同時更新 `draft` 與 `published` 的對應欄位**，只改這些欄位，不覆寫其他內容、不走一般發布流程、不產生新題庫版本。
- `published` 中不存在的次單元（尚未發布）只更新 `draft`；之後一般發布時帶入 `draft` 的區域欄位。
- 一般「發布課程」流程需確保以 `draft` 覆寫 `published` 時區域欄位一致（兩邊本來就同步，不會倒退）。
- 完成度函式修改見 5.5.1。

### 7.2 後端函式（`functions/src/index.ts`）
沿用既有教師身分與課程權限檢查。

| 函式 | 輸入 | 行為 |
|---|---|---|
| `setUnitVisibility` | `courseId`, `unitIds`（1–200）, `visibility`, `archiveLabel?` | transaction 同時更新 `draft` 與 `published`；`archived` 設 `archivedAt`；離開 `archived` 清除標籤與時間；寫紀錄 |
| `endCurrentExam` | `courseId`, `archiveLabel?` | 伺服器端讀取全部 `current` 改為 `archived`，共用標籤與時間；回傳清單；`current` 為空回傳明確錯誤；寫紀錄 |
| `renameArchiveLabel` | `courseId`, `from`, `to` | 批次改名；寫紀錄 |
| `setStudentNotice` | `courseId`, `text` | 驗證後寫入；寫紀錄 |

回報時更新函式總數。

### 7.3 學生端過濾
- `forClass()` 加入 `visibility === 'hidden'` 過濾，使 `bootstrap`、`getBank`、`submitAttempt`、`saveActivity`、`saveLearningEvents` 等既有防線自動生效。
- `getProgress`、`getHistory` 不回傳 `hidden` 次單元的資料（資料保留）。
- `saveExplanationResearchEvents` 同樣拒絕 `hidden` 次單元。
- 教師端、報表、預覽不受過濾。
- Firestore rules 不需功能變更，維持 deny-by-default，請覆核。

### 7.4 紀錄（研究用教學介入時間戳記）
- 集合：`courses/{courseId}/visibilityLog/{autoId}`（依既有命名慣例調整）。
- 欄位：`at`（server timestamp）、`actorUid`、`action`（`move`｜`endExam`｜`renameLabel`｜`notice`）、`unitIds`、`from`（各次單元前一區域）、`to`、`archiveLabel`、`notice`。
- 客戶端不可讀，教師需要時由 Console 查看。

### 7.5 既有資料與 Google Sheet 同步
- 既有次單元缺 `visibility` 視為 `current`，上線時學生端不會消失；教師上線後自行整理。
- 同步新建立的次單元一律 `hidden`。
- 既有次單元同步時不得覆寫 `visibility`、`archiveLabel`、`archivedAt`、`visibilityUpdatedAt`。
- 改單元名（`group`）不影響區域；改次單元名會產生新 `unitId`，新次單元為 `hidden`。
- `archiveCourse`、`migrateRoster` 行為不受影響，請確認。

### 7.8 錯題紀錄結構與更新（第四版新增）
- 既有結構為 `wrong: Record<version, string[]>`，改為 `Record<version, Record<questionId, { n, at }>>`。
- **讀取相容**：遇到舊的字串陣列時，視為 `{ n: 1, at: 0 }` 轉換後使用；`at: 0` 的紀錄在任何時間區間篩選中一律視為「超出區間」，只在「全部」時出現。學期初無學生資料，不需要遷移腳本。
- 更新規則：

| 模式 | 答對 | 答錯 |
|---|---|---|
| 完整測驗、完整閃卡、抽題、綜合練習 | 從錯題清單移除該題 | `n + 1`、`at = 交卷時間` |
| 錯題閃卡 | 不改變 | 不改變 |

- 所有更新一律在後端進行（`submitAttempt` 依正解批改後寫入），前端送來的對錯不予採用。
- 錯題閃卡不產生任何寫入。
- 時間以伺服器時間為準。

### 7.6 結算快照與完成度規則版本（教師決策：固定舊規則）
- 完成度函式改為依規則版本計算：`completion(course, progress, formulaVersion)`（命名依既有程式調整）。
  - `formulaVersion = 1`：既有規則（必做次單元 `best >= threshold`）。
  - `formulaVersion = 2`：1.3.0 新規則（第 5.5.1 節）。
- 新增常數 `CURRENT_COMPLETION_FORMULA_VERSION = 2`；學生端、教師即時報表一律使用目前版本。
- `createSnapshot()` 建立快照時寫入 `completionFormulaVersion: CURRENT_COMPLETION_FORMULA_VERSION`。
- 匯出快照時依快照內的 `completionFormulaVersion` 計算；**缺少此欄位的既有快照一律視為版本 1**。
- 版本 1 的計算邏輯保留，不得刪除；日後再改規則時新增版本號。
- 快照匯出畫面顯示「完成度規則：第 N 版」，避免教師混淆。

### 7.7 分數由後端批改（教師決策）
- 確認 `submitAttempt` 是否在後端依題庫正解重新批改分數，而非採用前端送來的分數或對錯。
- 若目前已由後端批改：維持並補測試（前端送出假分數或假對錯時，後端結果不受影響）。
- 若目前採用前端結果：**改為後端批改**。後端依 `unitId`、題庫版本與學生作答選項，對照已發布題庫計算對錯與分數；前端送來的分數、對錯欄位一律忽略。完整作答題數驗證、`best`、`wrong`、`attempted` 更新規則不變。
- 此項不需要再停下來詢問，但須在回報中說明原本的做法與修改內容。
