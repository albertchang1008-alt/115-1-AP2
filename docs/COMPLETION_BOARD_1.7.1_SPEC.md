# 1.7.1 完成度看板改版：各班比較＋學生×單元矩陣（Codex 規格）

2026-10-07 Claude 撰寫；教師選定方案 B（學生×單元矩陣），並要求「外面一層加上各班的比較」。

## 一、範圍與限制

- **只改前端顯示**：不改完成度公式（`completion`／`chapterCompletion`，公式版本 3）、不改後端、不改 Firestore 資料、不改 `getCompletion` 介面。
- 分支：以 `feature/1.7.0-practice-modes`（HEAD 8429640 之後）為基底，開 `feature/1.7.1-completion-board`；版本號 1.7.1（版本檔全部同步）。不 push、不部署、不動 main。
- 現有程式：`src/App.tsx` 的 `CompletionPage`（約 1299–1440 行）、`StudentDetail`；共用模型 `shared/model.ts`（`forClass`、`orderedChapters`、`chapterCompletion`、`completion`、`isOverdue`、`parseCourseTime`）。

## 二、要解決的問題（教師截圖）

1. 「單元完成度 0／6」算的是**單元**（Chapter），右欄「尚待完成」列的卻是**次單元**（題目分類），一人二十多項，數字和清單對不上。
2. 清單是一整段文字，看不出逾期、快到期、未開放。
3. 姓名直排、「查看」按鈕斷行。
4. 沒有全班總覽，更沒有班與班的比較。

## 三、版面：兩層

### 第一層：各班比較（進入頁面的預設畫面）

```
各班比較                          [更新全部班級]  [匯出各班比較 CSV]
              人數  全部完成  有逾期  平均完成   血液  心臟  心臟II  淋巴系統  …
全部班級       132     5       41    2.1/6     71%   55%   18%    64%
護二甲          45     3       12    2.4/6     80%   62%   20%    70%
護二乙          44     1       17    1.8/6     60%   45%   12%    58%
護二丙          43     1       12    2.1/6     73%   58%   22%    64%
```

- 列＝班級（`course.classIds`）；第一列「全部班級」為加總。點班級列 → 進入第二層。
- 欄位：
  - **人數**：該班名冊人數（含未登入者；沒有成績不視為零分，但仍計入分母，與現行完成度一致）。
  - **全部完成**：`completion(forClass(course, cl), p)` 的 `done === total` 且 `total > 0` 的人數。
  - **有逾期**：至少一個單元「逾期未完成」的人數（定義見四）。
  - **平均完成**：該班 `completion().done` 平均／應完成單元數（各班 `total` 可能不同，顯示該班的 total）。
  - **各單元完成率**：該單元 `chapterCompletion(...).done` 人數 ÷ 該班人數。欄位順序依 `orderedChapters(course)`（全課程），各班用 `forClass` 判斷：該班看不到或非必做的單元，格子顯示「—」（必做與選看不同的班，選看顯示灰字「選看」加完成率，不計入平均）。
- 色階：完成率格子以淺→深底色表示（0–100%），**同時一定要印百分比數字**，不靠顏色表達。單元欄標題下方小字顯示期限（`dueAt`，各班若有班級覆寫期限不同，標題顯示「各班不同」，格子 hover／點選顯示該班期限）。
- 資料載入：按「更新全部班級」時，前端依序對每個班呼叫既有 `getCompletion`，把 `next` 一頁頁讀完（每頁 50 人）；顯示進度「載入中：護二乙 50／44…」。不新增後端函式。讀過的班級資料快取在頁面狀態，進第二層不重讀；按「更新」才重讀。
- 用量提示：按鈕旁小字「會讀取全部學生的進度」。

### 第二層：班級學生×單元矩陣

```
← 各班比較   護二甲（45 人）   [更新] [搜尋] 排序：[學號▾] □只看有逾期  [匯出 CSV]
                    血液   心臟   心臟II  淋巴系統  呼吸系統
                   10/12  10/12  10/19   10/19    11/9
全班完成率            80%    62%    20%     70%      0%
陳盈宥  110510041  ●      ◐      ○逾     ●        ⊘      2/5  [查看]
謝○○    110510042  ●      ●      ◐      ●        ⊘      3/5  [查看]
```

- 欄＝`orderedChapters(forClass(course, cl))` 的單元；欄標題顯示單元名稱與期限。選看單元放最右、標題加「選看」、不計入 n／m。
- 第一列「全班完成率」：與第一層同一數字（同一函式算出，驗收會對照）。
- 每列：姓名（不換行）、學號、各單元格、`n／m`（＝`completion()`）、「查看」（沿用 `StudentDetail`）。帳號停用者姓名後加灰字「停用」。
- 格子狀態（一格一個單元，見四）：●完成、◐進行中、○未開始、⊘未開放；逾期未完成加紅框與「逾」字；逾期完成在 ● 旁加小字「逾」（灰）。**符號旁一律有文字或 aria-label**，不只靠顏色。
- 點格子 → 小視窗（popover，手機為底部抽屜）列出該單元底下的題目分類（次單元）：名稱、最高分／門檻、作答次數、首次達標時間（有 `passedAt` 才顯示）；以及必做活動完成數／總數。這取代舊的「尚待完成」整段文字。
- 工具列：搜尋（姓名／學號）、排序（學號／完成數少→多／逾期數多→少）、「只看有逾期」勾選、匯出 CSV。
- 第一欄（姓名＋學號）固定（sticky）；矩陣在 `.tablewrap` 內橫向捲動，**整頁不得橫向捲動**（390px 驗）。
- 移除舊表格的「尚待完成／逾期完成」文字欄。

## 四、格子狀態定義（新增純函式，放 `shared/`，附單元測試）

新增 `chapterCellState(course: Course /* 已 forClass */, name: string, p: Progress, now = Date.now())`，回傳：

| 狀態 | 條件（依序判斷） |
|---|---|
| `notOpen` ⊘ | 單元 `opensAt` 有值且 `parseCourseTime(opensAt) > now`，且未完成 |
| `done` ● | `chapterCompletion(...).done` |
| `inProgress` ◐ | 未完成，但該單元任一題目分類 `p.units[id].attempts > 0`，或任一必做活動已完成 |
| `notStarted` ○ | 其他 |

另回傳 `overdue: boolean`（`dueAt` 有值、`parseCourseTime(dueAt) < now`、且未完成）與 `lateDone: boolean`（已完成，且該單元有任一題目分類 `passedAt > parseCourseTime(dueAt)`；沒有 `passedAt` 就是 false）。

- 只做顯示，**不得**改變 `completion()` 的結果；`notOpen` 的必做單元仍算在 m 裡（與現行公式一致）。
- 「有逾期」人數＝至少一格 `overdue` 的學生數。

## 五、匯出

- 第二層 CSV：姓名、學號、班級、已完成、應完成，之後每個單元一欄，值為「完成／進行中／未開始／未開放／逾期未完成／逾期完成」。只匯出目前篩選後的學生。
- 第一層 CSV：班級、人數、全部完成、有逾期、平均完成、各單元完成率（%）。

## 六、驗收（Codex 自查後交 Claude）

1. 測試：`chapterCellState` 單元測試涵蓋六種情況（未開放、完成、進行中－作答、進行中－活動、未開始、逾期未完成、逾期完成、無 passedAt）；React 測試：第一層→點班級→第二層→點格子 popover→返回。
2. 一致性：用本機合成資料（至少 2 班、各 ≥8 人、含班級覆寫期限與單元可見性不同）驗證
   - 每位學生的 `n／m` 等於該列計分欄位 ● 的數量；
   - 第二層「全班完成率」＝第一層同班同單元的百分比；
   - 「全部班級」列＝各班加總後重算，不是各班百分比平均。
3. 截圖：第一層、第二層、popover，各 1280 與 390；390 整頁無橫向捲動、姓名不直排、按鈕不斷行。
4. `npm run check`、兩端 build、version:check 通過；舊測試全過。
5. 驗收報告 `docs/COMPLETION_BOARD_1.7.1_ACCEPTANCE.md`；commit 結尾 `[Codex]`；更新 handoff（≤150 行）與 DEVELOPMENT_LOG。
