# 互動教材雙軌規畫

依使用者 2026-09-12 補充，納入平台整合範圍。尚未實作／驗證。

## 學生體驗與教師診斷

- 學生保留教材自己的星星、徽章、煙火與闖關畫面；平台顯示「本活動已完成 100%」。不因診斷指標較低撤銷通關。
- 本活動完成不等於整門課完成、所有單元達標或測驗滿分。課程進度依班級適用單元及既定完成規則計算。
- 教師查看探索覆蓋、各題首次答案、每題嘗試次數、答題順序、提示使用及前景有效時間。保留未通關與中途離開的紀錄，避免只看成功者。
- 以中性描述呈現高／低探索與首次答對表現；不把低探索多次作答直接標籤為猜題、投機或不認真。
- 40% 探索覆蓋＋60% 首次答對率作為可選且版本化的暫定診斷指標，依每份教材實際節點數與題數計算，不能宣稱為真實理解或不可刷分。
- 無診斷串接的普通 HTML 可保留「確認已閱讀」；串接闖關教材由完成事件標記通關，手動確認僅表示閱讀，不能冒充闖關成功。
- 蒐集過程不打斷遊戲，但學生入口提供簡短學習紀錄用途說明；教師指標不作未告知的隱藏正式評分。

## 串接

教材事件 → 平台 iframe 橋接 → 驗證登入與課程／班級／單元授權 → Firestore → 教師診斷頁。

- 教材不接收學生姓名、信箱、學號或登入權杖；平台依登入身分歸屬紀錄。
- init 提供 protocolVersion、activityId、教材版本、sessionId；回傳事件含相同上下文及穩定事件 ID／序號。
- 平台驗證 iframe window、上下文、事件白名單、大小與數值界限。不得只憑 status=COMPLETED 將整門課標為完成。
- 原平台使用 ready/progress/completed 與 activityId；使用者範例 COURSE_PROGRESS_UPDATE 需明確轉接，不能直接貼入即視為相容。
- 分批保存、事件去重、暫存補送、完成確認 ACK；未收到確認顯示待同步，遊戲仍可正常進行。
- 首次作答資料不可因刷新／重玩覆寫；另存本次遊戲結果，避免多次嘗試被當作首次。
- 時間於頁面隱藏或閒置時停止累計。點擊節點不等於已閱讀，需分開呈現點開數與可觀測停留。
- 後端重算摘要，記錄教材版本與公式版本；前端資料仍可被修改，不能當作防作弊考試證據。

## 教師頁面

- 依課程、班級、單元、活動、教材版本篩選。
- 班級分布：探索節點比例 × 首次答對比例；呈現樣本數、未完成及缺資料情況。
- 個人紀錄：活動通關狀態與診斷分開；列出各題首次結果、重試數、提示及有效時間。
- 低探索高答對可能已有先備知識；高探索低答對可提示教師檢查概念與教材，不能單由行為判定原因。

## YouTube：自由觀看的補充教材

- 教師提供 YouTube 網址，可設定建議播放片段；學生自行決定是否觀看。
- 不要求看完、不設觀看比例門檻，不阻擋闖關、單元開放、完成度或成績。
- 保留播放位置與接續播放；既有觀看／播放結束紀錄僅供參考，不作必做完成條件。
- 未觀看不標示為「未完成」「落後」或需補交，活動清單標示「選看」。
- 外站觀看、無法嵌入或未回報，不扣分、不阻擋學習。
- 本輪不新增強制觀看偵測、觀看率要求或影片診斷評分；理解程度由題庫及互動活動提供依據。
- 互動教材診斷與 YouTube 參考紀錄分開，影片不得套用闖關教材的完成規則。

## GA4

Firestore 為課程名冊與個別診斷的主資料來源。GA4 可額外提供去識別的使用趨勢，不作個人成績唯一資料庫。GA4 不傳姓名、信箱或學號，使用獨立非識別代碼；串接需實際 GA4 設定，目前未提供。

參考：https://support.google.com/analytics/answer/6366371?hl=en

## 驗收

通關但首次答對少、全部首次答對、只探索未通關、重玩、刷新、背景閒置、離線補送、重複完成事件、偽造上下文、跨班存取、教師預覽不写正式紀錄、不同節點／題數教材，以及無 SDK 的普通教材。

YouTube 驗收：完全未觀看、只看一部分、拖曳至結尾、外站觀看及嵌入失敗，都不影響闖關、單元達標、成績或完成度；接續播放仍可用，教師頁不將未觀看列為落後。
