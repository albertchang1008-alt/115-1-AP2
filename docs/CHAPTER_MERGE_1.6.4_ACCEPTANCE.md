# 1.6.4 合併單元驗收（2026-10-03，Codex）

分支 feature/cardiac-output-visuals；未 push／部署，待 Claude 驗收。

後台「課程與教材 → 單元安排」只有無次單元的單元顯示「合併到…」。先保存草稿，選目標、預覽活動／同 ID 處理／受影響學生人數，最後按「確認合併到…」。換目標會清除舊預覽。補上空單元的複習考判斷防護，避免空陣列造成頁面錯誤。

## 資料處理

- 新 callable mergeChapter（asia-east1）：教師且列入該課程 teacherIds 才可呼叫；交易內再次檢查授權與來源無次單元。
- 草稿與已發布版本分別合併，保留各自原內容；已發布來源還有次單元，或已發布來源的目標不存在時拒絕，不會直接發布草稿。只在草稿有來源時不更動已發布版本。
- 目標活動先保留原順序，再依來源順序附加；同 ID 不增加、目標定義優先。沿用既有每單元 30 活動上限，超過則整筆拒絕。
- 目標共用設定保留，只補空白的開放／截止時間。chapterOverrides 逐班、逐欄補來源設定；目標 false／0 也算既有設定，不覆蓋；空白時間補來源。來源從 chapters、chapterOrder 及來源班級覆寫移除，次單元／classUnits／題庫不動。
- 讀取課程全部 progress 文件；對草稿與已發布來源活動 ID 的聯集，把精確來源鍵複製到目標。保留每個舊鍵及其他欄位；completed 取 OR，position／updatedAt 取最大，部分進度也保留。
- 受影響學生＝有任一來源活動進度鍵的 progress 文件數，包含尚未完成者；預覽不回傳學生身分或讀取研究資料。
- 預覽／提交皆由 transaction 讀取；確認權杖涵蓋兩份課程設定與受影響學生名單。設定／名單變動必須重新預覽；進度欄位更新則在提交讀取最新版。所有讀取先完成才寫入，課程移除與全體進度搬移一起提交。
- 新增 chapterMergeLog 記錄教師、來源、目標、活動 ID、人數與時間；研究／診斷／作答紀錄不改。未改完成度公式，仍為 v3。
- bootstrap 附加的發布／封存顯示欄位不影響草稿一致性判斷，欄位順序也不影響；提交回應保留發布／封存狀態。

## 已通過的測試

- Functions 真正 callable handler 使用記憶體資料庫執行：教師授權、防假確認、設定與人數變動拒絕、已發布來源有分類拒絕、預覽無寫入。
- 已完成來源＋未完成目標仍為完成；已完成目標＋未完成來源不降級；舊 key、其他活動、研究／診斷及進度額外欄位保留。
- 同 ID 只一份；班級設定目標優先、缺少欄位補齊；已發布課程不混入草稿名稱／門檻。
- 合併後兩活動＋一題目分類 totalRequired＝3，達標學生課程完成度 1／1，缺活動學生 0／1；來源不再算一個單元。
- 真實 React／Chrome 操作：只有空單元可合併、未保存停用、預覽人數／活動後才出現確認、換目標清空、確認後來源消失。記憶體預覽 API 支援相同操作。
- npm run check：119 前端／19 Functions、兩端 build、version:check 全過（1.6.4）。未連接正式 Firebase。
