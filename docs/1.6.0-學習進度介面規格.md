# 1.6.0「學習進度一目了然」介面規格

作者：Claude（2026-09-29）｜執行：Codex｜分支：自最新 HEAD 開 `feature/1.6.0-progress-ui`（若 1.5.0 尚未合併，自 `feature/1.5.0-review-exam` 開）

目標：學生在首頁與單元頁一眼看出**完成了什麼、還欠什麼、欠在哪裡**；必做單元與選看單元、必做活動與選做活動清楚分開。設計稿：Claude 設計畫布「學習進度介面規畫」（學生首頁桌機／手機、練習分頁桌機／手機）。本文件是完整規格，不需要看設計稿也能實作。

## 教師的決定（2026-09-29）

1. **只有「完整測驗」計分**。完整閃卡改為純練習，不再更新最高分。
2. 已經由完整閃卡取得的最高分**保留**，不重算；新規則自部署後生效。
3. 閃卡維持**整份**，不提供題數選擇。
4. **不排學習步驟**。練習方式（閃卡、抽題 10／20／30、錯題）全部並列，由學生自己選；介面只區分「計分」與「練習」。
5. **教師決定題目分類一律必做**：分類沿用所屬單元（Chapter）的 `required`，不提供分類層級的選做設定。只有選看單元（`Chapter.required === false`）及明確覆寫的選做活動不計入完成度。

## 一、狀態定義（`shared/model.ts` 新增純函式，前端共用）

每個項目（題目分類、學習活動）只有四種狀態：

| 狀態 | 題目分類 | 學習活動 |
|---|---|---|
| `done` | 最高分 ≥ 該生可見門檻 | 既有完成判定為完成 |
| `partial` | 有完整測驗但未達標；或無完整測驗但有任何練習紀錄（`attempted` > 0 或有錯題） | 有任何學習事件但未完成（互動教材有事件未 `complete`、影片有觀看秒數未達完成比例） |
| `todo` | 完全沒有紀錄 | 沒有任何事件（外部連結只有 `todo`／`done`） |
| `locked` | 所屬單元 `opensAt` 未到 | 同左 |

```ts
type ItemStatus = 'done' | 'partial' | 'todo' | 'locked';
interface ItemProgress {
  kind: 'category' | 'activity';
  id: string; title: string;
  required: boolean;
  phase?: 'pre' | 'class' | 'post';   // 活動的課前／課堂／課後
  status: ItemStatus;
  // 分類
  best?: number; threshold?: number; questionCount?: number;
  attempted?: number; wrongCount?: number; fullAttempts?: number;
  // 活動（依類型擇有）
  detail?: string;                    // 例：「節點 4 / 6・題目 6 / 11」
}
interface UnitProgressSummary {
  unitId: string; required: boolean;
  state: 'done' | 'inProgress' | 'todo' | 'overdue' | 'locked';
  dueAt?: string; daysLeft?: number;   // 負數＝已逾期天數
  requiredItems: ItemProgress[];       // 分類在前、活動在後，各依既有順序
  optionalItems: ItemProgress[];      // 選做活動；選看單元則包含該單元全部項目
  doneCount: number; totalCount: number; // 只算必做
  next?: ItemProgress;                 // 見「下一步」
}
export function itemStatusForCategory(...): ItemProgress;
export function itemStatusForActivity(...): ItemProgress;
export function summarizeUnit(unit, progress, now): UnitProgressSummary;
```

- 單元 `state`：`locked`（未開放）→ `done`（必做全 `done`）→ `overdue`（有 `dueAt`、`now > dueAt`、未完成）→ `inProgress`（任一必做項非 `todo`）→ `todo`。
- **下一步 `next`**：只從必做且非 `done` 的項目挑，順序：`partial` 優先 → `todo`；同狀態依分類在前、活動在後、各自原順序。**下一步只指出項目，不指定練習方式。** 必做全完成時，若有未看過的選做活動，`next` 可為該活動並標示「選做」。
- 選做活動與選看單元的項目：不進 `doneCount`／`totalCount`，不參與 `overdue`，永不顯示逾期。
- 分類的 `required` 一律使用所屬單元（Chapter）的必做狀態；`forClass()` 套用班級覆寫後也必須把 `Chapter.required` 同步到各 `Unit.required`，維持 v1／v2 舊完成度與教師待完成名單相容。
- 活動（2026-09-29 盤點結果：目前沒有獨立欄位，由 `isRequiredActivity()` 依活動類型與 `tracking` 推導）：新增**選填的覆寫欄位** `Activity.required?: boolean`。`isRequiredActivity()` 改為：`required` 有值就用它，`undefined` 時沿用現有推導。舊資料不遷移，行為完全不變。教師後台活動設定加「必做」三選一：「依活動類型（預設）／必做／選做」，預設項旁顯示目前推導結果（例：「依活動類型：必做」）。`saveCourse` 只加型別驗證。
- 首頁資料（盤點結果）：學生首頁只讀一份 `progress` 文件，最高分、看過題數、錯題數、活動狀態皆已在內，本版**不得新增 Firestore 讀取**；第八節的延遲載入不需要實作。
- 「看過幾題」用 1.2.0 的 `Progress.attempted`；錯題數用目前版本的 `wrong`。

## 二、計分規則變更（`functions/src/index.ts`）

- `submitAttempt`：只有 `mode === 'quiz'` 且 `full` 的作答更新最高分；`mode === 'flashcard'` 照常寫錯題、`attempted`、作答紀錄，但**不更新最高分、不寫 `passedAt`**。
- 已存在的最高分不動（不重算、不遷移）。
- `CURRENT_COMPLETION_FORMULA_VERSION` **維持 3**（公式仍是「最高分 ≥ 門檻」，只是最高分的來源變窄）；在 `DEVELOPMENT_LOG.md` 與 handoff 註明 1.6.0 起閃卡不計分、舊分數保留。
- 綜合練習（`submitMixedAttempts`）行為不變。
- 需要記錄「完整測驗次數」`fullAttempts`：若 progress 已有可推得的欄位就沿用；沒有則在 `Progress.units[unitId]` 新增 `fullAttempts?: number`，完整測驗交卷時 +1（舊資料顯示為空，不回填）。

## 三、學生首頁（`src/Student.tsx`）

**頂端待辦列**（白底卡片一列，手機改三行）：
- 紅色「已逾期 k 項」：逾期單元內未完成的必做項目數。
- 橘色「7 天內到期 k 項」：已開放、`dueAt` 在 7 天內、未完成的必做項目數。
- 「必做單元完成 a / b」：`locked` 的單元不算入 b。
- 「查看全部待辦」：在列下方展開清單，依單元分組列出上述項目，每項可點進該單元。數量為 0 的項目不顯示；全部為 0 時顯示「目前沒有待辦」。

**單元列表**分兩區：「必做單元」「選看單元・不計完成度」。

**必做單元卡（收合時）**，由上而下：
1. 徽章列：`03 必做單元`（灰）＋狀態徽章（已完成＝綠、進行中＝橘、有逾期＝紅、未開始＝灰）＋期限文字（「期限 10/12・還有 13 天」；逾期改紅字「期限 9/26・已過 3 天」；已完成改「9/18 完成」若有 `passedAt` 可推得，否則省略）。
2. 標題，右側「完成 9 / 17 項」。
3. 格子條：每個必做項目一格（14×14，圓角 3），分類與活動之間留 12px 空隔。`done` 實心綠、`partial` 實心橘、`todo` 白底灰框、逾期單元內未完成者實心紅。需 `aria-label` 描述數量。
4. 文字：「題目分類 2 / 6 達標・活動 7 / 11 完成」。
5. 非已完成的單元顯示「下一步」列：藍底「還沒達標：心動週期與心音（最高 17 / 80 分）」或「還沒完成：課後・影片：心音聽診」＋按鈕「去練習／前往」，點擊直接到該分類列（練習分頁並捲動到該列）或該活動。逾期單元改紅底「已逾期：…」。
6. 右上展開箭頭（44×44 可點區）。

**展開後**加兩區（所有單元預設收合；展開狀態可存 `localStorage`，讀寫包 try/catch）：
- 「題目分類」標題列右側「門檻 80 分・只有完整測驗計分」。逐列：狀態圖示＋名稱＋右側說明：
  - `partial` 有分數：「最高 17・還差 63 分・錯題 5」
  - `partial` 無完整測驗：「只做過練習，還沒完整測驗」
  - `todo`：「還沒開始」
  - `done` 的全部合併成一列「已達標 2 個：心臟構造 86、心臟血液供應 82 ▾」，點開才列出。
- 「學習活動」依課前／課堂／課後分組；每組標題「課堂・2 / 3 完成」，只列未完成項目，已完成收成「已完成 2 項 ▾」；整組都完成時整組縮成一列「課前・3 項都完成」。活動說明：互動教材「節點 4 / 6・題目 6 / 11」；影片「看到 3:20 / 8:00」或「還沒開始」；外部連結「還沒開啟」；未完成者附期限。
- 最後一列灰底：「選做（不計完成度）・1 項活動，看過 1 項 ▾」，只列選做活動，展開後以「看過／還沒看過」列出，圖示用眼睛，不用空心圓。題目分類不在此區出現。

**未開放單元**：徽章「鎖頭圖示＋10/5 開放」（線條圖示，不用 emoji），標題灰色，文字「題目分類 5・活動 8・開放後才計入待辦」，不顯示格子條、下一步、展開。

**選看單元卡**：淺灰底（`#fafbfc`），徽章「選看單元」（眼睛圖示），標題，「看過 2 / 6 項」；無狀態徽章、無格子條、無下一步、無期限警示；展開後列出項目（看過／還沒看過）。「看過」定義：分類有任何紀錄、活動有任何事件。

**複習考（1.5.0）單元卡**：沿用本規格卡片結構，必做項目只有一格（複習考本身），下一步為「開始作答（N 題）」；保留 1.5.0 的「作業・複習考」與「逾期完成」標示。

**練習分頁**：

1. 摘要列：兩個數字卡「分類達標 2 / 6」「達標門檻 80 分」＋說明兩行：`[計分]` 只有完整測驗計入最高分；`[練習]` 閃卡、抽題、錯題都不影響完成度，想用哪種就用哪種。取代現有的「已達標分類 0 / 8」與「完整測驗與完整閃卡計入最高成績…」說明文字。
2. 分兩區，區標題附數量：
   - 「還沒達標」：`partial` 在前、`todo` 在後，同狀態維持原順序。
   - 「已達標」。
   任何一區沒有項目就不顯示該區。
3. 每列（桌機 grid：`24px | 1fr | 190px | auto`）：
   - 狀態圖示（`done` 綠勾圈、`partial` 橘半圓、`todo` 灰空圈）。
   - 名稱不加「必做／選做」徽章；下一行小字「60 題・看過 42 題・錯題 5・完整測驗 2 次」（沒開始：「40 題・還沒開始」）。選看單元內的分類列整列使用淺灰樣式，但不標示為選做分類。
   - 分數欄：「最高 17 / 80」＋分數條（寬度＝分數%，未達標橘、達標綠，80% 處畫 2px 門檻線）＋下方小字（「還差 63 分」「已達標」「只做過練習」）；沒有完整測驗時寫「還沒完整測驗」、分數條空。
   - 按鈕區分兩組，中間 1px 分隔線，組上方有小標：
     - 「計分」：`完整測驗`（藍底藍框，全頁唯一有色的按鈕樣式）。
     - 「練習・不計分」：`閃卡`、小字「抽題」後接 `10` `20` `30`、`錯題 k`（白底灰框）。錯題 0 時按鈕保持可點（點了顯示「目前沒有錯題」），樣式改虛線框淡字。
   - 所有按鈕一律顯示，不依狀態隱藏或改變主次。
4. 從首頁「去練習」進來時捲動到目標列並短暫高亮（2 秒淡藍底）。
5. 複習考單元的練習分頁維持 1.5.0 規格（只有開始作答與錯題），套用本節的列樣式與狀態圖示。

## 五、手機版（寬度 ≤ 640px）

- 首頁：待辦列改三行可點列；卡片格子 12×12、間距 3；徽章可換行；展開內容同桌機。
- 單元頁分頁：四等分，名稱下一行狀態小字。
- 摘要：兩個數字卡並排＋一行說明。
- 練習列改直向：圖示＋名稱＋徽章 → 小字 → 「最高 17 / 80」左、「還差 63 分」右 → 分數條 → 兩顆等寬按鈕 `完整測驗・計分`、`練習 ▾`。`練習 ▾` 展開列內選單：閃卡（整份 N 張）、抽題 10 題、抽題 20 題、抽題 30 題、錯題複習（k 題），每項 44px 高。一次只展開一個。
- 「已達標」區在手機預設收成一列按鈕，點開展開。
- 所有可點區 ≥ 44px。

## 六、視覺規則

- 沿用現有字型與色調（Noto Sans TC、淺灰底白卡）。狀態色：綠 `#2f7d4f`（文字 `#226b40`、底 `#e5f2ea`）、橘 `#e0a23a`（文字 `#8a4f00`、底 `#fbefd9`）、紅 `#c4382f`（文字 `#a3231b`、底 `#fbe7e5`）、藍 `#1b559a`（底 `#e7effa`、框 `#9dbbe0`）、次要文字 `#5d6d7e`。
- 狀態不能只靠顏色：一定搭配圖示形狀（勾圈／半圓／空圈／驚嘆號／鎖頭／眼睛）與文字。
- 圖示用線條 SVG，不用 emoji。
- 用詞：分類與必做活動用「達標／完成／還沒開始」；選做活動與選看單元用「看過／還沒看過」；不用「失敗」「落後」。
